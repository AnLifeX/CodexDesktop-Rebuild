# Windows 迁移检查（2026-10-27）

检查范围：实际发布程序的 ASAR 中脚本及配置、解包资源和插件启动脚本、安装/更新/救援/清理代码、当前用户相关注册表、桌面/开始菜单/启动/任务栏快捷方式、计划任务、插件缓存和用户配置。

| 问题 | 处理与验证 |
|---|---|
| 旧程序的保留逻辑可能把更高版本移入 `.old` | 比对安装状态、版本目录、RELEASES；旧进程不能改变新版状态或移动新版。已覆盖 r1 与下一正式版的排序和旧进程回归测试。 |
| 新版确认会被旧 `CurrentApp` 拦住 | 允许较新版本提交健康状态，拒绝过期进程。已用实际 r1 验证更新器入口和根目录 Codex.exe。 |
| 主进程和后台工作线程仍向旧根目录写日志 | 两处日志实现都随新安装根目录使用 `Programs\Codex\Logs`；实际启动测试确认不创建旧根目录。 |
| Windows“程序”兼容目录导致快捷方式扫描失败 | 不递归进入目录联接；单元测试和迁移集成测试已覆盖。 |
| `codex://` 仍注册到历史桌面便携版 | 成功启动时修复协议和 App Paths 注册，不能仅替换两个已知根目录。集成测试使用独立注册表前缀验证。 |
| 更新或手动还原的快捷方式仍带旧版本工作目录 | 成功启动重新规范相关快捷方式；测试在首次迁移后人为还原旧工作目录，再次确认并检查修复。 |
| 首次成功启动后才发现的旧版本缺少清理期限 | 每次确认都为未计时的已登记旧版补记期限，按当前版本首次健康时间计算。 |
| 用户删除旧根目录后仍尝试重复写迁移标记 | 标记只在提交迁移时写入；源目录已不存在时清除待清理源记录，不重建目录。 |

本机配置扫描中仅有两条过去执行命令的历史记录包含旧程序路径，没有发现插件启动配置仍引用旧安装根目录。安装缓存、图标和启动清单在目标位置存在；本机更新缓存文件数量及总大小一致。迁移流程本身对完整源树逐文件验证 SHA-256，包含隐藏文件和空目录。

以下是保留的数据位置，不是安装迁移遗漏：`CODEX_HOME`（默认 `.codex`）、`%APPDATA%\Codex` 的用户数据、`%LOCALAPPDATA%\OpenAI\Codex` 的运行时和工作区、OpenAI 浏览器扩展宿主目录。历史日志和回收站内容不作批量字符串改写。

本机旧目录完整文件再现与用户执行过部分回收站还原相符，不能归因于程序重新复制整套安装。清理仅按已确认状态和期限执行，本次检查没有删除安装副本或回收站内容。

边界：脚本静态扫描及安装/回退/启动测试不能覆盖所有第三方插件在长期使用中的动态行为；没有通过卸载当前工作的程序来验证真实用户卸载。
