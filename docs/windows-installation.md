# Windows 安装目录规范

状态：已实现，等待发布及实际安装验收。现有本机安装没有被手动迁移。

本项目定位为官方桌面端的替代版本，应用名称保持 `Codex`。新安装直接使用目标目录；旧安装通过更新后的首次启动自动迁移，不引入改名、双版本共存或数据隔离方案。

## 目标布局

安装根目录固定为 `%LOCALAPPDATA%\Programs\Codex`，根目录本身不包含版本号。

```text
%LOCALAPPDATA%\Programs\Codex\
├── Codex.exe                 固定启动入口，由启动桩定位已安装版本
├── ChatGPT.exe               上游主程序名称对应的兼容启动入口
├── Update.exe                Squirrel 更新器
├── CodexUpdater.exe          故障救援更新器
├── app-<版本号>\             Squirrel 管理的实际程序与资源
├── .old\                     暂存旧版本，避免 Squirrel 提前删除
├── .codex-install.xml         启动确认和清理期限
├── packages\                 更新包和安装状态
├── update-cache\             下载缓存
└── CodexInstall.log           迁移或清理错误日志（按需生成）
```

现有发布版仍在 `%LOCALAPPDATA%\Codex`；只有安装或更新到包含迁移逻辑的新构建后，才会自动切换目录。

## 目录与入口规则

1. 用户快捷方式使用根目录下的 `Update.exe --processStart ChatGPT.exe`，由 Squirrel 选择当前版本，图标使用根目录 `ChatGPT.exe`。保留固定 `Codex.exe` 兼容入口，不把版本目录写进快捷方式。
2. `app-<版本号>` 是当前版本目录。旧版本暂存在 `.old\<编号>\app-<版本>\`，正在运行且无法移走的旧版本暂留原位。短目录名避免触发 .NET Framework 路径长度限制，额外一层编号也避免 Superba 将旧版当成当前版。这不等于已经提供任意版本回滚功能。
3. 不把 `app-<版本号>` 的完整路径写死在快捷方式、启动项、第三方集成配置或用户文档中。第三方工具若必须读取实际资源目录，需要单独验证其当前版本选择逻辑。
4. 注册表卸载记录的 `InstallLocation` 指向固定根目录。卸载命令、更新缓存和救援更新器均以实际安装根目录解析路径。
5. 配置、登录状态和会话继续遵循现有 `CODEX_HOME` 规则；不因调整程序目录而搬动、删除或隔离用户数据。

## 迁移要求

- 安装器使用完整包调用 Squirrel 的 `--update`，不使用会先删除安装根目录的 `--install`。新安装使用目标目录，覆盖安装沿用已有根目录。
- 老版本先在旧目录完成更新。新版首次普通启动后，由独立临时进程等待旧进程退出，将整个根目录复制到 `Programs\Codex.migrating`。逐文件校验大小及 SHA-256，包含程序、资源、更新包、缓存、日志、隐藏文件、空目录和自定义文件；遇到符号链接或目录联接报错并保留源安装。
- 校验通过才发布目标目录并启动新版。目标已存在时不覆盖、不合并。最多等待 10 分钟完成主界面确认，再切换当前用户卸载注册、启动注册、桌面、开始菜单、启动文件夹及任务栏中的相关链接；快捷方式通过根目录更新器启动当前版本。
- 失败时保留源文件并重新启动源目录的程序。同一个失败版本不反复自动迁移；首次启动失败的目标副本改名为 `Codex.failed-<标识>` 供排查。
- 旧根目录在迁移成功后保留 24 小时；保留期内旧入口转向新目录。用户配置、登录状态、会话及 Electron 用户数据位置保持原规则，不随程序路径迁移。
- 无需单独发布过渡版本：第一个包含迁移逻辑的新版本自身完成过渡。旧版本正常下载并启动它后才会生效。

## 旧版本清理

- 成功条件：主应用 `index.html` 加载完成且应用根节点已渲染、页面有文字，稳定运行 30 秒，期间没有主框架加载失败、导航或渲染进程崩溃。内嵌页面加载不取消确认；页面延迟渲染或确认程序执行失败时每 5 秒重试。更新窗口、空白页和 DevTools 不计入。
- 确认成功前同步当前版本的救援更新器和启动清单到根目录，补偿旧更新流程没有执行安装钩子的情况。确认以维护程序成功退出为准。
- 保留和确认操作先比对安装状态、实际版本目录及 `packages\RELEASES`；旧进程不能重置当前版本、覆盖新版救援器或将更新版本移入 `.old`。只登记版本号严格更旧的目录。
- 新安装目录中的主进程和后台工作线程均将日志写入 `Programs\Codex\Logs`，不会为了写日志重建旧安装根目录。已提交的迁移不再重复写入旧根目录标记。
- 每次成功启动重新规范相关快捷方式，修复更新流程或手动还原带回的版本目录工作路径；`codex://` 与 Windows App Paths 注册也指向当前固定入口，覆盖历史便携版注册。成功启动后才发现的旧版本也补记清理期限。
- 从首次确认成功开始保留旧版 24 小时，重复启动不延长期限。没有成功确认不删除；当前版和未登记为旧版的待安装版本不删除。
- 用户级计划任务在到期后运行；关机、睡眠或未登录时，在下次可运行时执行。文件占用或删除失败保留原文件并每小时重试，应用下次启动也重试。
- 清理只针对登记的旧版和已成功迁移的旧根目录；校验绝对路径，不跟随符号链接和目录联接。不会清理 `.codex`、项目文件或其他应用目录。卸载时移除任务。
- 发布前仍需真实安装验收全新安装、旧版升级、固定入口启动、后续更新、救援更新和卸载。

## 实现边界

继续使用现有 Squirrel 更新机制，保留内部 `app-<版本号>` 目录。固定的安装根目录和启动入口用于屏蔽内部版本路径。

如果以后要求实际程序和资源也全部平铺、完全取消版本子目录，需要重新设计安装和更新流程，不属于本次目录规范。
